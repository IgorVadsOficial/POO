1. Entenda o sistema antes dos detalhes

O projeto representa um pequeno sistema de reservas de voos. O passageiro pode criar, cancelar e pagar reservas; o operador pode criar e cancelar em nome do passageiro; o voo controla assentos, reservas, aeroportos e tripulação.

Quem participa?

Passageiro solicita a reserva. Operador auxilia no atendimento. Aeroviário representa um integrante da tripulação.

O que é registrado?

A classe Reserva guarda código, situação de pagamento e referências ao passageiro, ao voo e, quando houver, ao operador.

Onde acontece?

A classe Voo guarda origem, destino, quantidade de assentos, reservas e tripulantes. Os aeroportos são objetos da classe Aeroporto.

Ideia central para a defesa: o diagrama mostra a estrutura estática do sistema — classes, atributos, métodos e relacionamentos. O código transforma essa estrutura em objetos e implementa o comportamento, como verificar assentos, criar reservas e atualizar listas.

2. O diagrama completo, para você visualizar

A imagem abaixo é o diagrama enviado. Observe primeiro as caixas, depois as linhas entre elas e, por último, as multiplicidades e setas.

Como ler uma classe UML

Nome da classe: aparece na primeira divisão da caixa.
Atributos: dados que cada objeto guarda, na divisão do meio.
Métodos: operações que os objetos podem executar, na divisão inferior.
− significa membro privado; + significa membro público.
Tipo após dois-pontos: por exemplo, nome : String indica um atributo textual.
Tipo no UML: indica o tipo esperado do atributo ou retorno. O Python deste arquivo não usa anotações como : str ou -> str; os tipos são inferidos pelos valores atribuídos e retornados.
Seta com triângulo vazio: indica herança, apontando para a classe mais geral.
Losango vazio: indica agregação, uma relação de “todo e parte” mais fraca que composição.
Atenção: há um detalhe nas multiplicidades da ligação entre Passageiro e Reserva que parece estar invertido no desenho. Isso será explicado na seção de relacionamentos, sem alterar a imagem original.
Classes do diagrama

3. Cada classe explicada, uma por uma

Uma classe é um modelo. Quando o programa cria um objeto, esse objeto possui os atributos definidos pela classe e pode executar os métodos dela.

Passageiro

Representa a pessoa que utiliza o sistema para fazer reservas.

Atributos

  • nome : String — nome do passageiro.
  • cpf : String — identificação do passageiro.
  • reservas : Reserva[] — conjunto/lista de reservas relacionadas a ele.

Métodos

  • criarReserva(voo, operador) — tenta criar uma reserva para um voo.
  • cancelarReserva(reserva) — remove a reserva do passageiro e do voo.
  • pagarReserva(reserva) — marca a reserva como paga.
  • getReservas() — fornece acesso à lista de reservas.

No Python, o segundo parâmetro de criarReserva é opcional: operador=None.

Reserva

É o registro que conecta um passageiro a um voo e registra se o pagamento foi realizado.

Atributos

  • codigo : String — identificador, como R1.
  • paga : boolean — informa se foi paga.
  • passageiro : Passageiro — objeto ao qual a reserva pertence.
  • voo : Voo — voo reservado.
  • operador : Operador — operador associado, quando a reserva é feita por ele.

Métodos

  • getCodigo() — retorna o código.
  • getPaga() — retorna o estado do pagamento.
  • setPaga(paga) — altera esse estado.
  • getVoo() — retorna o voo relacionado.
Voo

Representa o voo e concentra informações operacionais necessárias às reservas.

Atributos

  • codigo : String — código do voo.
  • horario : String e data : String — horário e data.
  • assentos : int — quantidade total de assentos oferecidos.
  • partida : Aeroporto e destino : Aeroporto — objetos que representam origem e destino.
  • reservas : Reserva[] — reservas vinculadas ao voo.
  • tripulantes : Aeroviario[] — integrantes da tripulação.

Métodos

  • assentosLivres() — calcula os assentos disponíveis.
  • getTripulacao() — retorna a lista de tripulantes.
  • getTipo() — identifica o voo como nacional ou internacional.
  • getReservas() — retorna a lista de reservas.
Aeroporto

Representa os aeroportos utilizados como origem ou destino dos voos.

Atributos

  • nome : String — nome do aeroporto.
  • cidade : String — cidade em que fica.
  • pais : String — país do aeroporto.
  • capacidade : int — capacidade informada para o aeroporto.

Método

  • getPais() — retorna o país. O método é usado por Voo para comparar origem e destino.

No código, a capacidade é armazenada, mas não participa de nenhuma validação.

Funcionario abstrata

É uma classe genérica para representar funcionários. Não é criada diretamente; serve como base para classes mais específicas.

Atributo

  • nome : String — nome herdado pelas subclasses.

Métodos

  • getNome() — retorna o nome.
  • getCargo() : String — método abstrato: as subclasses devem fornecer sua implementação.

No desenho, <<abstract>> e o nome em itálico indicam que a classe é abstrata.

Operador

Representa o funcionário que atende o passageiro e pode realizar operações em nome dele.

Atributos próprios

  • matricula : String — identificação funcional.
  • reservas : Reserva[] — reservas criadas por esse operador.

Também herda o atributo nome e o método getNome() de Funcionario.

Métodos próprios

  • criarReserva(passageiro, voo) — solicita ao passageiro a criação e registra a reserva se der certo.
  • cancelarReserva(passageiro, reserva) — solicita o cancelamento e atualiza a lista do operador.
  • getCargo() : String — retorna “Operador”.
Aeroviario

Representa um integrante da equipe que compõe a tripulação do voo.

Atributo próprio

  • funcao : String — função exercida, como “Piloto”.

Também herda nome e getNome() de Funcionario.

Métodos próprios

  • getFuncao() — retorna a função específica.
  • getCargo() : String — implementa o método abstrato da classe-pai, retornando a função.
Lendo as linhas

4. Relacionamentos: como explicar as ligações

As linhas não são enfeites. Elas mostram que os objetos se conhecem ou colaboram. A multiplicidade indica quantos objetos de uma classe podem estar associados a um objeto da outra.

Passageiro — Reserva

Significado esperado: um passageiro pode ter zero ou várias reservas; cada reserva pertence a um passageiro.

O código implementa isso com a lista self.__reservas em Passageiro e com a referência self.__passageiro em Reserva.

Detalhe importante no desenho: a multiplicidade 0..* aparece junto de Passageiro e 1 junto de Reserva. Pela convenção UML, os números junto às extremidades descrevem quantas instâncias daquela extremidade se relacionam a uma instância da outra. Para o significado implementado pelo código, o usual seria colocar 1 junto de Passageiro e 0..* junto de Reserva. Portanto, essa ligação parece estar invertida no diagrama.

Voo — Reserva

Um voo pode possuir várias reservas, inclusive nenhuma. Cada reserva está vinculada a um único voo.

O código guarda a lista em Voo.__reservas. O objeto Reserva guarda a referência ao voo em Reserva.__voo.

O losango vazio junto de Voo representa agregação: o voo agrupa reservas, mas a relação é mais fraca do que uma composição.

Operador — Reserva

O desenho indica que um operador pode estar associado a várias reservas e que uma reserva pode ter zero ou um operador.

Isso combina com o código: uma reserva criada diretamente pelo passageiro recebe operador=None; quando é criada pelo operador, recebe a referência self do operador.

Voo — Aeroviario

A legenda “É tripulado por” indica que o voo possui integrantes da tripulação. No código, Voo.__tripulantes é uma lista de objetos Aeroviario.

O método getTripulacao() entrega essa lista, que é preenchida no programa principal.

O diagrama não mostra multiplicidades nessa associação; por isso, não se deve afirmar que ele especifica uma quantidade exata.

Voo — Aeroporto: “Parte de”

Representa o aeroporto de origem. No construtor de Voo, ele é recebido no parâmetro partida e guardado em self.__partida.

Voo — Aeroporto: “Chega em”

Representa o aeroporto de destino. É recebido pelo parâmetro destino e guardado em self.__destino.

O programa cria um voo que parte de Natal e chega a Lisboa.

Operador → Funcionario

É uma relação de herança. Operador é um tipo específico de Funcionario. Ele herda nome e getNome(), mas implementa seu próprio getCargo().

A seta com triângulo vazio aponta para a classe mais geral, Funcionario.

Aeroviario → Funcionario

Também é herança. Aeroviario recebe nome e getNome() da classe-pai e acrescenta o atributo funcao, além de implementar getCargo().

Como explicar multiplicidades: 1 significa exatamente um; 0..1 significa nenhum ou um; 0..* significa nenhum, um ou vários; 1..* significa um ou vários. Sempre leia o número que está próximo à extremidade da classe que ele quantifica.

5. O código completo explicado por etapas

Agora vamos percorrer o arquivo EX04(4).py na mesma ordem em que o interpretador encontra as definições. Os trechos são do código enviado, com comentários explicativos abaixo de cada parte.

5.1. Importação das ferramentas para abstração

from abc import ABC, abstractmethod

ABC permite criar uma classe abstrata. abstractmethod marca um método que precisa ser implementado pelas classes concretas que herdam dessa classe.

Esses recursos serão usados em Funcionario. O objetivo é definir uma estrutura comum para os funcionários sem obrigar que todos tenham o mesmo cargo.

5.2. Classe Aeroporto

class Aeroporto:
    def __init__(self, nome, cidade, pais, capacidade):
        self.__nome = nome
        self.__cidade = cidade
        self.__pais = pais
        self.__capacidade = capacidade

    def getPais(self):
        return self.__pais

__init__ é o construtor: é executado quando um objeto Aeroporto é criado. Recebe nome, cidade, país e capacidade e armazena os valores nos atributos do objeto.

self representa a própria instância. Por exemplo, self.__nome é o nome guardado naquele aeroporto.

Os dois sublinhados no início — como em __pais — ativam o mecanismo de name mangling do Python, usado para dificultar o acesso direto e evitar colisões de nomes em subclasses. Em explicações introdutórias, costuma-se chamar esses atributos de privados.

getPais() retorna o país. O Voo usa esse método para comparar o país do aeroporto de partida com o país do aeroporto de destino.

5.3. Classe abstrata Funcionario

class Funcionario(ABC):
    def __init__(self, nome):
        self.__nome = nome

    def getNome(self):
        return self.__nome

    @abstractmethod
    def getCargo(self):
        pass

Funcionario(ABC) indica que a classe herda de ABC e pode conter métodos abstratos.

O construtor guarda o nome. getNome() devolve esse nome, e as subclasses herdam esse método sem precisar reescrevê-lo.

@abstractmethod marca getCargo() como obrigatório para as subclasses concretas. O pass não executa uma ação: ele apenas deixa o corpo do método vazio na classe abstrata.

Por isso, a classe define o que um funcionário precisa oferecer, enquanto cada subclasse define como informar seu cargo.

5.4. Classe Aeroviario: herança e super()

class Aeroviario(Funcionario):
    def __init__(self, nome, funcao):
        super().__init__(nome)
        self.__funcao = funcao

    def getFuncao(self):
        return self.__funcao

    def getCargo(self):
        return self.__funcao

Aeroviario(Funcionario) declara que Aeroviario herda de Funcionario.

super().__init__(nome) chama o construtor da classe-pai. Assim, a parte herdada do objeto — o nome — é inicializada pela própria classe Funcionario. Não é a mesma coisa que escrever self.__nome = nome dentro de Aeroviario; a chamada reutiliza o construtor da superclasse.

Depois, Aeroviario acrescenta seu atributo próprio __funcao. getFuncao() devolve essa função. getCargo() implementa o método abstrato herdado e retorna a função do aeroviário.

Exemplo do programa: Carlos é criado com a função “Piloto”.

5.5. Classe Voo

class Voo:
    def __init__(self, codigo, horario, data, partida, destino, assentos):
        self.__codigo = codigo
        self.__horario = horario
        self.__data = data
        self.__partida = partida
        self.__destino = destino
        self.__assentos = assentos
        self.__reservas = []
        self.__tripulantes = []

    def assentosLivres(self):
        return self.__assentos - len(self.__reservas)

    def getTripulacao(self):
        return self.__tripulantes

    def getTipo(self):
        if self.__partida.getPais() == self.__destino.getPais():
            return "NACIONAL"
        return "INTERNACIONAL"

    def getReservas(self):
        return self.__reservas

Construtor: recebe os dados do voo e guarda cada um em um atributo. Os parâmetros partida e destino recebem objetos Aeroporto, não apenas textos.

__reservas = [] cria uma lista inicialmente vazia de reservas. __tripulantes = [] cria uma lista inicialmente vazia de aeroviários. Essas listas são inicializadas por voo, dentro do construtor, para que cada voo tenha suas próprias coleções.

assentosLivres() calcula assentos totais menos a quantidade de reservas já registradas. len(self.__reservas) conta quantos elementos existem na lista. Exemplo: com 2 assentos e 1 reserva, retorna 1.

getTripulacao() e getReservas() retornam as listas correspondentes. No código, quem recebe essas listas pode acrescentar ou remover elementos.

getTipo() pergunta o país dos aeroportos de partida e destino. Se os países forem iguais, retorna “NACIONAL”; caso contrário, retorna “INTERNACIONAL”. Por isso Aeroporto fornece getPais().

5.6. Classe Reserva

class Reserva:
    def __init__(self, codigo, passageiro, voo, operador):
        self.__codigo = codigo
        self.__paga = False
        self.__passageiro = passageiro
        self.__voo = voo
        self.__operador = operador

    def getCodigo(self):
        return self.__codigo

    def getPaga(self):
        return self.__paga

    def setPaga(self, paga):
        self.__paga = paga

    def getVoo(self):
        return self.__voo

Reserva armazena os dados do registro. O código identifica a reserva; __paga começa como False, pois uma reserva recém-criada ainda não foi paga.

Os atributos __passageiro, __voo e __operador guardam referências a outros objetos. Isso concretiza os relacionamentos do UML: uma Reserva sabe a qual passageiro e voo está ligada e qual operador participou, quando houver.

getCodigo() e getPaga() consultam valores; setPaga(paga) altera a situação do pagamento; getVoo() devolve o objeto voo. O cancelamento usa getVoo() para localizar a lista em que a reserva deve ser removida.

5.7. Classe Passageiro: o núcleo da criação de reservas

class Passageiro:
    def __init__(self, nome, cpf):
        self.__nome = nome
        self.__cpf = cpf
        self.__reservas = []

    def criarReserva(self, voo, operador=None):
        if voo.assentosLivres() == 0:
            return None
        reserva = Reserva("R" + str(len(self.__reservas) + 1), self, voo, operador)
        voo.getReservas().append(reserva)
        self.__reservas.append(reserva)
        return reserva

    def cancelarReserva(self, reserva):
        reserva.getVoo().getReservas().remove(reserva)
        self.__reservas.remove(reserva)

    def pagarReserva(self, reserva):
        reserva.setPaga(True)

    def getReservas(self):
        return self.__reservas

Construtor: guarda nome e CPF e cria a lista vazia de reservas daquele passageiro.

criarReserva(voo, operador=None): primeiro verifica se o voo tem assentos livres. Se o resultado for exatamente zero, retorna None e não cria reserva. O parâmetro operador é opcional: quando o próprio passageiro cria a reserva, fica None; quando um operador intermedeia a operação, o objeto Operador é passado.

Se houver assento, o código forma um identificador como “R1”. A expressão len(self.__reservas) + 1 calcula um número com base na quantidade atual de reservas do passageiro. Em seguida cria um objeto Reserva, passando o próprio passageiro (self), o voo e o operador.

Depois, a mesma reserva é adicionada a duas listas: à lista do voo e à lista do passageiro. Isso mantém os dois lados da relação atualizados. Por fim, o método retorna o objeto criado.

cancelarReserva(reserva): usa reserva.getVoo() para encontrar o voo daquela reserva e remove o registro da lista do voo. Depois remove o mesmo registro da lista do passageiro.

pagarReserva(reserva): chama setPaga(True), alterando o atributo de pagamento para verdadeiro.

getReservas() devolve a lista de reservas do passageiro.

5.8. Classe Operador: herança e colaboração

class Operador(Funcionario):
    def __init__(self, nome, matricula):
        super().__init__(nome)
        self.__matricula = matricula
        self.__reservas = []

    def criarReserva(self, passageiro, voo):
        reserva = passageiro.criarReserva(voo, self)
        if reserva:
            self.__reservas.append(reserva)
        return reserva

    def cancelarReserva(self, passageiro, reserva):
        passageiro.cancelarReserva(reserva)
        if reserva in self.__reservas:
            self.__reservas.remove(reserva)

    def getCargo(self):
        return "Operador"

Operador(Funcionario) também herda de Funcionario. O construtor usa super().__init__(nome) para inicializar o nome herdado, guarda a matrícula e cria sua própria lista de reservas.

criarReserva(passageiro, voo) não duplica a lógica de criação. Ele delega o trabalho a passageiro.criarReserva(voo, self). O self passado como terceiro argumento é o próprio operador, permitindo que a Reserva registre quem a criou. Se o resultado for diferente de None, a reserva também é adicionada à lista particular do operador. O método retorna a reserva ou None.

cancelarReserva(...) delega a retirada principal ao passageiro. Depois, se a reserva estiver na lista do operador, remove-a dessa lista também.

getCargo() implementa o método abstrato da classe Funcionario e retorna a palavra “Operador”.

5.9. Criação dos objetos iniciais

natal = Aeroporto("Aeroporto de Natal", "Natal", "Brasil", 20)
lisboa = Aeroporto("Humberto Delgado", "Lisboa", "Portugal", 40)

voo = Voo("AD100", "08:00", "20/12/2026", natal, lisboa, 2)
voo.getTripulacao().append(Aeroviario("Carlos", "Piloto"))

passageiro = Passageiro(input("Nome do passageiro: "), "000")

perfil = input("1 = passageiro, 2 = operador: ")

O programa cria dois aeroportos: Natal, no Brasil, e Lisboa, em Portugal. Depois cria o voo AD100, às 08:00 do dia 20/12/2026, com dois assentos. Os objetos natal e lisboa são passados ao construtor de Voo como partida e destino.

Em seguida, cria um Aeroviario chamado Carlos, função Piloto, e o adiciona à tripulação do voo. O passageiro é criado com nome informado pelo usuário e CPF fixo “000”. A operadora Ana, matrícula OP01, também é criada.

Por fim, o programa pergunta qual perfil será utilizado: 1 para passageiro ou 2 para operador. Essa resposta será usada nas decisões do menu.

5.10. Função escolher_reserva()

def escolher_reserva():
    for i, r in enumerate(passageiro.getReservas(), 1):
        print(i, "-", r.getCodigo(), "| paga:", r.getPaga())
    return passageiro.getReservas()[int(input("Qual reserva? ")) - 1]

Essa função serve para permitir que o usuário escolha uma das reservas já pertencentes ao passageiro.

enumerate(passageiro.getReservas(), 1) percorre a lista e fornece dois valores: o número de exibição, começando em 1, e o próprio objeto reserva. O r representa a reserva atual.

O print mostra número, código e estado de pagamento. Depois, o usuário digita o número da reserva. Como listas Python começam no índice 0, a expressão subtrai 1 do número digitado. Assim, a opção 1 acessa o índice 0, a opção 2 acessa o índice 1, e assim por diante.

Como explicar oralmente: “Eu criei essa função para não repetir o mesmo processo de listar e selecionar uma reserva nas opções de cancelar e pagar. Ela percorre as reservas, mostra os dados principais e retorna o objeto escolhido.”

Limitação: a função não verifica se a lista está vazia nem se o número digitado está dentro do intervalo. Se o usuário escolher quando não há reservas, ou informar um número inválido, pode ocorrer IndexError ou ValueError.

5.11. Laço principal do menu

while True:
    print("\nVoo", voo.getTipo(), "| assentos livres:", voo.assentosLivres())
    print("1 Reservar | 2 Cancelar | 3 Pagar | 4 Tripulação | 0 Sair")
    opcao = input("> ")

while True inicia um laço que continua indefinidamente até encontrar um break. A cada repetição, o programa mostra o tipo do voo e a quantidade de assentos livres, apresenta as opções e lê a escolha do usuário.

5.12. Opção 1 — reservar

if opcao == "1":
    if perfil == "1":
        reserva = passageiro.criarReserva(voo)
    else:
        reserva = operador.criarReserva(passageiro, voo)
    print("Reservado!" if reserva else "Voo cheio.")

Se o perfil for passageiro, o programa chama diretamente passageiro.criarReserva(voo). Se for operador, chama operador.criarReserva(passageiro, voo), que registra o operador na reserva.

Depois utiliza uma expressão condicional: se a variável reserva contém um objeto, mostra “Reservado!”; se contém None, mostra “Voo cheio.”. Isso ocorre porque criarReserva retorna None quando não há assentos livres.

5.13. Opção 2 — cancelar

elif opcao == "2":
    reserva = escolher_reserva()
    if perfil == "1":
        passageiro.cancelarReserva(reserva)
    else:
        operador.cancelarReserva(passageiro, reserva)
    print("Cancelada.")

Primeiro, o programa chama escolher_reserva() para descobrir qual registro será cancelado. Depois verifica o perfil: o passageiro cancela diretamente; o operador executa o método de cancelamento do operador, que delega a remoção ao passageiro e atualiza sua própria lista quando necessário.

5.14. Opção 3 — pagar

elif opcao == "3":
    if perfil == "1":
        passageiro.pagarReserva(escolher_reserva())
        print("Paga!")
    else:
        print("Só o passageiro paga.")

O pagamento só é permitido no fluxo do perfil de passageiro. O programa seleciona uma reserva e a envia para pagarReserva(), que altera paga para True. Quando o perfil é operador, exibe a mensagem informando que somente o passageiro paga.

5.15. Opção 4 — listar tripulação

elif opcao == "4":
    for a in voo.getTripulacao():
        print("-", a.getNome(), a.getCargo())

O laço percorre a lista de tripulantes do voo. Para cada aeroviário, imprime o nome herdado de Funcionario e o cargo/função retornado por getCargo(). É um exemplo de uso dos métodos herdados e sobrescritos.

5.16. Opção 0 — sair

elif opcao == "0":
    break

O break interrompe o while True e encerra o menu. Como não há um bloco final de tratamento para outras entradas, opções diferentes de 0, 1, 2, 3 e 4 simplesmente não executam nenhuma ação e o laço recomeça.

Análise crítica

6. O que está alinhado e o que merece atenção

É importante demonstrar que você não apenas decorou o diagrama: você sabe relacionar o modelo ao comportamento real do programa e reconhecer o que ainda não foi implementado.

Correspondências principais: as sete classes do UML estão no Python; os atributos centrais aparecem nos construtores; Operador e Aeroviario herdam de Funcionario; Voo mantém reservas e tripulantes; Reserva guarda referências ao passageiro, ao voo e ao operador; e os métodos de criar, cancelar e pagar reserva estão implementados.

1. Multiplicidade Passageiro–Reserva

Como explicado acima, o desenho coloca 0..* junto de Passageiro e 1 junto de Reserva. Para representar o código, a posição esperada é 1 junto de Passageiro e 0..* junto de Reserva.

2. Tipos do UML e Python

O UML informa tipos como String, int e boolean. O código Python não declara essas anotações formalmente; ele atribui valores e retorna objetos desses tipos durante a execução. Por exemplo, getCargo retorna texto, mas não possui anotação -> str.

3. CPF fixo

Embora a classe receba CPF no construtor, o programa principal sempre passa o texto “000”. Portanto, o CPF ainda não é solicitado nem validado pelo sistema.

4. Capacidade dos aeroportos

O atributo capacidade é armazenado em Aeroporto, mas não é utilizado para limitar voos, passageiros ou reservas. A disponibilidade de lugares vem do atributo assentos do Voo.

5. Validação da escolha de reserva

escolher_reserva() pressupõe que existe ao menos uma reserva e que a opção digitada é válida. Faltam verificações para lista vazia, letras e números fora do intervalo.

6. Código da reserva

O identificador usa o tamanho atual da lista mais um. Depois de cancelar uma reserva, um código já usado pode ser gerado novamente. Exemplo: com R1 e R2, ao cancelar R1, a próxima pode receber R2 outra vez.

7. Perfil informado

O programa verifica se o perfil é “1”; qualquer outro valor entra no fluxo de operador. Não há validação explícita para aceitar somente 1 ou 2.

8. Regras simplificadas

O código não verifica se uma reserva já foi paga antes de pagar novamente, se o passageiro é realmente dono da reserva selecionada, nem se o operador associado é o mesmo que está cancelando.

9. Programa demonstrativo

O fluxo cria um único voo, um passageiro, um operador e um tripulante. É uma demonstração das classes e operações, não um sistema completo com cadastro e armazenamento persistente.

Como responder se o professor perguntar sobre as limitações: “O modelo de classes está representado e as operações centrais estão implementadas. O programa é uma versão didática simplificada. Há validações e funcionalidades que poderiam ser acrescentadas, como validar a seleção da reserva, gerar códigos realmente únicos, solicitar o CPF e utilizar a capacidade do aeroporto. Eu reconheço esses pontos como melhorias, não como funcionalidades que o código já realiza.”

Fala 1 — Apresentação do diagrama UML

“O diagrama representa a estrutura de um sistema de reservas de voos, utilizando o paradigma de programação orientada a objetos. Ele está organizado em classes, e cada classe reúne atributos, que representam os dados, e métodos, que representam os comportamentos dos objetos.

Começando pela classe Passageiro, ela representa o usuário que realiza as reservas. Ela possui nome, CPF e uma coleção de reservas. Seus métodos permitem criar, cancelar e pagar uma reserva, além de consultar as reservas associadas ao passageiro.

A classe Reserva representa o registro de uma reserva. Ela possui um código, um atributo booleano que informa se está paga e referências ao passageiro, ao voo e ao operador, quando houver. Seus métodos permitem consultar o código, consultar e alterar o estado do pagamento e acessar o voo relacionado.

A classe Voo concentra as informações do voo, como código, horário, data, quantidade de assentos, aeroporto de partida, aeroporto de destino, reservas e tripulantes. Ela possui métodos para calcular os assentos livres, consultar a tripulação, identificar se o voo é nacional ou internacional e acessar as reservas.

A classe Aeroporto armazena nome, cidade, país e capacidade. O método getPais permite consultar o país do aeroporto. Essa informação é importante porque a classe Voo compara o país de origem com o país de destino: se forem iguais, o voo é classificado como nacional; se forem diferentes, como internacional.

Também temos a classe Funcionario, que é abstrata. Ela reúne características comuns aos funcionários, como o nome, e define os métodos getNome e getCargo. O método getCargo é abstrato, então as classes concretas que herdam de Funcionario precisam implementar esse comportamento.

As classes Operador e Aeroviario herdam de Funcionario. Operador acrescenta matrícula e uma coleção de reservas pelas quais é responsável, além dos métodos para criar e cancelar reservas. Aeroviario acrescenta a função exercida, como piloto, e implementa getCargo retornando essa função.

Em relação aos relacionamentos, Passageiro se relaciona com Reserva porque um passageiro pode possuir várias reservas, enquanto cada reserva pertence a um passageiro. Reserva também se relaciona com Voo: um voo pode ter várias reservas e cada reserva está vinculada a um voo. O operador pode estar associado às reservas que criou, mas uma reserva também pode existir sem operador, quando é feita diretamente pelo passageiro.

O voo é tripulado por aeroviários e possui dois relacionamentos com Aeroporto: um representa de onde o voo parte e o outro representa onde ele chega. Por fim, as setas com triângulo vazio mostram a herança de Operador e Aeroviario em relação à classe Funcionario.

Portanto, o diagrama descreve como o sistema está organizado e como seus objetos se relacionam. Ele funciona como um planejamento da estrutura que será implementada no código Python.”

Observação para a defesa: no desenho enviado, as multiplicidades da ligação Passageiro–Reserva parecem estar trocadas. A fala acima apresenta a regra coerente com a implementação. Caso o professor observe o desenho, reconheça que a posição dos rótulos precisa ser ajustada.

Fala 2 — Apresentação do código Python

“No código, eu implementei a estrutura do diagrama utilizando classes e objetos em Python. A primeira linha importa ABC e abstractmethod, que são recursos utilizados para criar uma classe abstrata e definir métodos que precisam ser implementados pelas subclasses.

A primeira classe é Aeroporto. Seu construtor recebe nome, cidade, país e capacidade e armazena essas informações em atributos. O método getPais retorna o país do aeroporto, informação que será utilizada posteriormente pela classe Voo.

Depois, temos Funcionario, que herda de ABC e funciona como classe abstrata. Ela armazena o nome e disponibiliza getNome. O método getCargo é marcado com abstractmethod, obrigando as subclasses concretas a implementar essa operação.

Em seguida, Aeroviario herda de Funcionario. No construtor, utilizo super().__init__(nome) para reaproveitar a inicialização do nome feita pela classe-pai. Depois, armazeno a função específica do aeroviário. O método getFuncao retorna essa função e getCargo implementa o método abstrato herdado.

A classe Voo recebe os dados do voo, incluindo os objetos Aeroporto de partida e destino. Ela também inicializa duas listas: uma para reservas e outra para tripulantes. O método assentosLivres subtrai a quantidade de reservas do total de assentos. O método getTipo compara os países dos aeroportos e retorna NACIONAL ou INTERNACIONAL. Os outros métodos permitem consultar as listas de tripulação e reservas.

A classe Reserva armazena o código, a situação do pagamento e as referências ao passageiro, ao voo e ao operador. A reserva começa com paga igual a False. Os métodos getters permitem consultar código, pagamento e voo, enquanto setPaga altera a situação do pagamento.

Na classe Passageiro, o construtor guarda nome e CPF e inicia uma lista de reservas. O método criarReserva primeiro verifica se ainda existem assentos. Caso não existam, retorna None. Caso exista disponibilidade, cria um objeto Reserva, adiciona esse objeto tanto à lista do voo quanto à lista do passageiro e retorna a reserva criada. O método cancelarReserva remove a reserva das duas listas. Já pagarReserva marca a reserva como paga, e getReservas permite consultar a coleção do passageiro.

Depois temos Operador, que também herda de Funcionario e utiliza super para inicializar o nome. Ele guarda a matrícula e sua lista de reservas. Seu método criarReserva chama o método do passageiro, passando o próprio operador como argumento. Assim, a reserva consegue registrar quem participou da criação. Se a criação funcionar, o operador também adiciona a reserva à sua lista. O método cancelarReserva delega o cancelamento ao passageiro e atualiza a lista do operador. Por fim, getCargo retorna “Operador”.

Na parte principal, o programa instancia os aeroportos de Natal e Lisboa, cria um voo com dois assentos e adiciona Carlos, que é um aeroviário com função de piloto, à tripulação. Depois solicita o nome do passageiro, cria a operadora Ana e pergunta qual perfil será utilizado.

A função escolher_reserva evita repetir a lógica de listar e selecionar uma reserva. Ela percorre a lista do passageiro, mostra o número, o código e se a reserva está paga. Em seguida, recebe a opção do usuário e subtrai um do número digitado para converter a numeração apresentada, que começa em um, para o índice da lista Python, que começa em zero.

Por último, o while True mantém o menu em execução. Na opção 1, cria uma reserva como passageiro ou por meio do operador. Na opção 2, seleciona e cancela uma reserva. Na opção 3, permite que o passageiro pague a reserva e impede essa ação no perfil de operador. Na opção 4, percorre a tripulação e mostra nome e cargo. Na opção 0, o break encerra o laço.

Assim, o código transforma o modelo UML em um programa funcional de demonstração: as classes representam as entidades do sistema, os relacionamentos são implementados por referências e listas, a herança reaproveita características de Funcionario e os métodos executam as operações de reserva, cancelamento, pagamento e consulta da tripulação.”

Treino de perguntas

8. Perguntas que o professor pode fazer

Abra cada pergunta e treine responder sem olhar primeiro para a explicação.

1. Qual é a diferença entre classe e objeto?

Classe é o modelo que define atributos e métodos. Objeto é uma instância concreta dessa classe. Aeroporto é a classe; natal, criado com Aeroporto(...), é um objeto.

2. O que significa self?

É a referência à instância atual. Permite acessar e modificar os atributos e métodos daquele objeto, como self.__nome.

3. Por que os atributos começam com dois sublinhados?

Para acionar o name mangling do Python, dificultando o acesso direto e evitando colisões de nomes. É comum chamar esse padrão de atributo privado, embora Python não tenha privacidade rígida como algumas outras linguagens.

4. O que é uma classe abstrata?

É uma classe usada como base e que pode definir operações obrigatórias para as subclasses. Neste projeto, Funcionario define getCargo() como abstrato e não deve ser instanciada diretamente enquanto tiver método abstrato não implementado.

5. Para que servem ABC e @abstractmethod?

ABC permite definir a classe como base abstrata; @abstractmethod marca o método que precisa ser implementado pelas subclasses concretas.

6. O que faz super().__init__(nome)?

Chama o construtor da classe-pai, Funcionario, para inicializar o nome herdado. Assim, Operador e Aeroviario reutilizam a inicialização já definida.

7. Qual é a diferença entre herança e associação?

Herança representa uma relação “é um tipo de”: Operador é um Funcionario. Associação representa colaboração ou vínculo entre objetos: uma Reserva está ligada a um Voo.

8. Por que Reserva guarda objetos e não apenas textos?

Porque as referências permitem acessar os próprios objetos relacionados. Por exemplo, a reserva chama getVoo() para chegar ao voo e remover-se da lista dele no cancelamento.

9. Por que criarReserva retorna None quando o voo está cheio?

None sinaliza que não foi possível criar a reserva. O programa principal usa esse retorno para exibir “Voo cheio.” em vez de “Reservado!”.

10. O que significa len(self.__reservas)?

Retorna a quantidade de elementos na lista de reservas do passageiro. É usado para calcular o próximo número do código e, na classe Voo, para calcular quantos assentos já foram ocupados.

11. Por que a reserva é adicionada a duas listas?

Porque ela deve aparecer tanto nas reservas do passageiro quanto nas reservas do voo. Quando é criada ou cancelada, as duas coleções precisam ser atualizadas para manter a consistência.

12. O que acontece quando o passageiro paga?

pagarReserva chama reserva.setPaga(True), alterando o atributo booleano paga de False para True.

13. Por que o voo é internacional nesse exemplo?

Porque o aeroporto de partida é Natal, no Brasil, e o destino é Lisboa, em Portugal. Como getPais() retorna valores diferentes, getTipo() devolve “INTERNACIONAL”.

14. O que o enumerate(..., 1) faz em escolher_reserva?

Percorre a lista fornecendo um contador que começa em 1 junto com cada elemento. Isso facilita mostrar opções começando em 1, embora a lista Python use índices iniciados em 0. Por isso o código subtrai 1 do número escolhido.

15. O que while True e break fazem?

while True mantém o menu repetindo. break interrompe o laço quando o usuário seleciona a opção 0.

16. O código está 100% igual ao UML?

As classes, os atributos principais, os métodos e os relacionamentos centrais estão implementados. Porém, há uma provável inversão das multiplicidades na ligação Passageiro–Reserva do desenho. Além disso, o código possui simplificações, como CPF fixo, capacidade do aeroporto não utilizada e ausência de validação na seleção de reservas.
